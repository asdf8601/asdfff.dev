In 2024 I [got zsh down to 50 ms](/posts/zsh-on-macos-profiling/). Two years
later it was back at 130 ms. Every new tool asks for one line in your
`.zshrc`, and 10 ms at a time it adds up.

This time I asked Claude Code to profile my zsh.

<Card title="TL;DR">
  I inlined the output of `brew shellenv`, cached the podman socket, used
  `compinit -C`, removed envman and swapped autoenv for direnv (well, Claude did).

  | | `zsh -i` | `zsh -l -i` |
  |---|---|---|
  | Before | 129 ms | 145 ms |
  | Four fixes | 52 ms | 54 ms |
  | direnv | 36 ms | (not measured) |
</Card>

## Measure

```zsh
$ hyperfine -N -w 3 -r 20 'zsh -i -c exit' 'zsh -l -i -c exit' 'zsh -f -c exit'
Benchmark 1: zsh -i -c exit (20 runs)
  Wall Time    128.7 ms ±  8.4 ms   110.0 ms … 143.8 ms
Benchmark 2: zsh -l -i -c exit (20 runs)
  Wall Time    145.2 ms ± 18.0 ms   118.9 ms … 172.7 ms   +12.8%
Benchmark 3: zsh -f -c exit (20 runs)
  Wall Time      4.3 ms ±  0.3 ms     3.8 ms …   4.9 ms   -96.6%  (29.8x faster)
```

`zsh -f` starts with no config. zsh takes 4 ms, the other 125 are mine.
macOS terminals open login shells (`-l`), which also read `.zprofile`.

## Where the time goes

`zprof` only sees functions, so an `eval "$(brew shellenv)"` never shows up.
To see every line, I ran zsh with `-x` and the time in `PS4`:

```zsh
PS4='+%D{%s.%6.}|%x|%I> ' zsh -l -i -x -c exit 2> xtrace.log
```

Each line carries a timestamp, the file and the line number. This script
subtracts each timestamp from the next and sums per file:

```python
import sys, re, collections

rows = []
for line in open(sys.argv[1], errors="replace"):
    m = re.match(r"^\++(\d+\.\d+)\|([^|]*)\|(\d+)> ?(.*)", line)
    if m:
        rows.append((float(m[1]), m[2], int(m[3]), m[4][:110]))

byfile, slow = collections.Counter(), []
for a, b in zip(rows, rows[1:]):
    d = b[0] - a[0]
    byfile[a[1]] += d
    slow.append((d, a))

print("-- per file (ms)")
for f, d in byfile.most_common(15):
    print(f"{d*1000:7.1f}  {f}")
print("\n-- slowest single lines (ms)")
for d, a in sorted(slow, reverse=True)[:20]:
    print(f"{d*1000:7.1f}  {a[1]}:{a[2]}  {a[3]}")
```

```
   32.2  ~/.zshrc
```

Tracing inflates the times. So I measured each suspect alone with
hyperfine, minus the 4 ms baseline:

| Piece | Cost |
|---|---|
| `brew shellenv` (login only) | ~33 ms |
| autoenv | ~30 ms |
| `podman machine inspect` | ~27 ms |
| `compinit` | ~25 ms |
| envman | ~15 ms |

## Fixes

### `brew shellenv`

The `eval` launches brew in every login shell to print a few `export` lines that never
change. I pasted them into `.zprofile`:

```zsh
# static output of `brew shellenv zsh`, inlined because running brew costs ~30ms
export HOMEBREW_PREFIX="/opt/homebrew"
export HOMEBREW_CELLAR="/opt/homebrew/Cellar"
export HOMEBREW_REPOSITORY="/opt/homebrew"
fpath[1,0]="/opt/homebrew/share/zsh/site-functions"
export PATH="/opt/homebrew/bin:/opt/homebrew/sbin${PATH+:$PATH}"
export INFOPATH="/opt/homebrew/share/info:${INFOPATH:-}"
```

### podman

`DOCKER_HOST` points at the podman socket. The path changes because the
socket lives under the `TMPDIR` the machine started with, and asking podman
for it cost 27 ms. Now I read it from a file and refresh it in the background:

```zsh
_podman_host_cache=$HOME/.cache/podman-docker-host
[[ -s $_podman_host_cache ]] && export DOCKER_HOST=$(<$_podman_host_cache)
(
    sock=$(podman machine inspect --format '{{.ConnectionInfo.PodmanSocket.Path}}' 2>/dev/null) \
        && [[ -n $sock ]] && print -r -- "unix://$sock" >| $_podman_host_cache
) &!
```

`&!` backgrounds it and disowns it. If the path changes, the next shell
already has it.

### `compinit`

I wasn't calling it. bun's completion script was, without `-C`, so
`compaudit` ran on every start. `compinit -C` skips it: 29 ms → 15 ms,
timing `compinit` alone under `zsh -f`. The full check runs once a day:

```zsh
autoload -Uz compinit
_zcompdump_stale=(${ZDOTDIR:-$HOME}/.zcompdump(N.mh+24))
if (( $#_zcompdump_stale )); then
    compinit && touch ${ZDOTDIR:-$HOME}/.zcompdump
else
    compinit -C
fi
unset _zcompdump_stale
```

`(N.mh+24)` only matches the file if it's older than 24 hours. If you
install something and its completions don't show up, `rm ~/.zcompdump`.

### envman

Some installer added it. It ran four `touch` commands and sourced four empty
files. I removed it.

With these four:

```zsh
$ hyperfine -N -w 3 -r 20 'zsh -i -c exit' 'zsh -l -i -c exit'
Benchmark 1: zsh -i -c exit (20 runs)
  Wall Time     51.7 ms ±  2.2 ms    47.4 ms …  55.6 ms
Benchmark 2: zsh -l -i -c exit (20 runs)
  Wall Time     53.6 ms ±  2.3 ms    47.6 ms …  59.2 ms   +3.7%
```

### autoenv → direnv

autoenv was the slowest thing left (30 ms). It also sources every `.autoenv`
in your shell, and with `AUTOENV_ASSUME_YES=1` any cloned repo ran code on
`cd`. Leaving the directory kept the venv and the variables set.

[direnv](https://direnv.net/) runs the `.envrc` separately, applies only
what changed and undoes it when you leave. A new `.envrc` won't run until
you `direnv allow` it. The hook costs ~8 ms:

```zsh
eval "$(direnv hook zsh)"
```

The catch is that direnv only exports variables. The functions and the SSH
tunnel I had in some `.autoenv` files moved into scripts.

