He pasado de más de 50 pestañas de Chrome a más de 20 sesiones de Claude
Code, una por ventana de tmux. Eso me da cinco problemas:

1. no perder ninguna sesión
2. saber cuál me necesita
3. encontrar una sesión
4. no olvidar trabajo
5. repartir trabajo entre sesiones

Aquí sesión es un chat de Claude Code. Cuando hablo de las de tmux lo digo.

## No perder ninguna sesión

Al principio recuperaba las sesiones con tmux-resurrect y
`claude --continue`. tmux-resurrect relanza el comando de cada pane tras un
reinicio. Pero
`claude --continue` abre el último chat del directorio, así que cinco panes
en la misma carpeta volvían los cinco al mismo chat.

### Cada pane vuelve a su chat: `ccr`

`ccr` (con `alias cc=ccr`) fija un uuid de sesión en su propia línea de
comandos:

```zsh
#!/bin/zsh
if [[ "$1" == -* ]]; then
  exec claude "$@"
fi

id="$1"
if [[ "$id" =~ '^[0-9a-f]{8}-[0-9a-f]{4}-[0-9a-f]{4}-[0-9a-f]{4}-[0-9a-f]{12}$' ]]; then
  shift
else
  exec "$0" "$(uuidgen | tr '[:upper:]' '[:lower:]')" "$@"
fi

session_files=(~/.claude/projects/*/"$id".jsonl(N))
if (( ${#session_files} )); then
  claude --resume "$id" "$@"
else
  claude --session-id "$id" "$@"
fi
```

- Sin argumentos se relanza a sí mismo con un uuid nuevo, así el uuid queda
  en el `argv` del proceso, que es lo que guarda resurrect.
- Ejecuta `claude` como hijo y no con `exec`. El proceso de `claude` aparece
  en `ps` sin argumentos, así que el uuid tiene que quedarse en el wrapper
  para que resurrect lo vea.
- Con un uuid que ya existe hace `--resume`, así que `cc <uuid>` ancla un
  chat viejo a un pane.
- Los flags (`cc -c`, `cc -r`) pasan tal cual a `claude`.

### Autosave

```tmux
set -g @resurrect-processes '~ipython ~ccr "claude->claude-restore"'
set -g @resurrect-strategy-nvim 'session'
set -g @continuum-restore 'on'
set -g @continuum-save-interval '5'
```

tmux-continuum guarda cada 5 minutos y restaura al arrancar tmux. Relanza
`ccr` e `ipython`, y nvim con su sesión.

Un pane guardado como `claude` a secas pasa por `claude-restore`. Este script
pequeño saca el uuid del `--resume` o `--session-id` guardado y lanza `ccr <uuid>`. Si no hay
uuid, deja una shell con un aviso. Antes caía en `claude --continue`, y eso
devolvía el chat equivocado.

### `prefix r` es un peligro

`prefix r` recarga la config con `source-file`, y eso machaca
`status-right`. tmux-continuum guarda desde un comando metido en
`status-right`, así que tras recargar el autosave se moría en silencio hasta
el siguiente reinicio. Un
reinicio me devolvió un layout de dos semanas antes.

El arreglo es poner el hook a mano en la config, con la ruta absoluta del
plugin. `#{@cc_count}` es el contador de la sección siguiente.

```tmux
set -g status-right "#{@cc_count}#[default]#($HOME/.tmux/plugins/tmux-continuum/scripts/continuum_save.sh) %Y-%m-%d  %H:%M "
```

Después de recargar, este comando tiene que dar 1:

```bash
tmux show-option -gv status-right | grep -c continuum_save
```

## Saber cuál me necesita

Con veinte sesiones tenía que ir ventana por ventana para ver cuál había
terminado y cuál esperaba un permiso. Los nombres no ayudaban, porque casi
todas las ventanas se llamaban como la misma carpeta del repo.

### Un icono de estado por ventana

Unos hooks de Claude Code en `~/.claude/settings.json` llaman a
`cc-tmux-state`. Guarda el estado de cada pane y pinta un icono delante del
nombre de la ventana: amarillo trabajando, verde terminado, rojo pidiendo
permiso.

| Hook de Claude Code                  | Comando                   |
| ------------------------------------ | ------------------------- |
| `UserPromptSubmit`                   | `cc-tmux-state working`   |
| `Notification` (`permission_prompt`) | `cc-tmux-state attention` |
| `PostToolUse`                        | `cc-tmux-state resume`    |
| `Stop`                               | `cc-tmux-state done`      |
| `SessionEnd`                         | `cc-tmux-state clear`     |

```tmux
setw -g window-status-format " #I #{@cc}#[default]#W "
set-hook -g pane-focus-in 'run-shell -b "$HOME/.local/bin/cc-tmux-state seen #{pane_id}"'
```

`pane-focus-in` marca el pane como visto, así el verde dura hasta que miro
la ventana. El rojo dura hasta que respondo, porque solo lo quita
`PostToolUse` cuando la herramienta aprobada ya ha corrido.

![Barra de estado de tmux con un icono por ventana: rojo pide permiso, verde terminado, amarillo trabajando, y el contador de rojos y verdes a la derecha](/images/tmux-status-bar.png)

A la derecha, `#{@cc_count}` cuenta los panes en rojo y en verde. `prefix A`
abre un popup con ellos, primero los que piden permiso y luego los turnos
terminados que no he visto, de más viejo a más nuevo.

![Demo animada: login-timeout se pone en rojo al pedir permiso, prefix A abre el popup con ese pane primero, Enter salta a él, al responder Yes pasa a amarillo y el contador baja a dos verdes](/images/tmux-attention.gif)

### Ventanas con un nombre útil

El hook `Stop` llama a `cc-tmux-name`, que renombra la ventana con el título
de la sesión. Solo toca ventanas de un pane con nombre genérico (el
directorio, `zsh`) o que ya nombró antes, nunca un nombre puesto a mano.

Cuando el título automático es largo o vago, con el skill `/tmux-name` la
propia sesión se pone nombre, `<ticket>-<slug>` si hay ticket o PR. Renombra
la ventana y el chat para que el hook no lo pise.

### Avisos por Telegram

Las notificaciones de escritorio de Ghostty no atraviesan tmux (probé OSC 9
y 777, con y sin `allow-passthrough`). Cuando quiero saber que algo
terminó, un bot me manda un Telegram. Es un `curl` a
`api.telegram.org/bot<token>/sendMessage`, envuelto en un skill.

## Encontrar una sesión

Encontrar la sesión de una PR concreta, entre ventanas abiertas y chats
cerrados, me llevaba un rato cada vez. Y en una sola sesión de tmux, lo que
estaba haciendo se mezclaba con lo terminado y con lo que esperaba a otro
equipo.

### Índice de sesiones: `prefix g` y `prefix G`

`sessions.py` está sin publicar, porque está atado a mi Jira y a mis repos.
Lee todos los transcripts de `~/.claude/projects/` y guarda un índice local con
una línea por sesión: última actividad, directorio y título. Cada línea lleva también las
PRs y tickets que esa sesión tocó (abrió la PR, hizo push, movió el ticket),
con su estado en vivo.

```bash
python3 ~/.claude/skills/sessions/sessions.py [all] [query] [--sync]
```

Sin argumentos abre fzf sobre todas las sesiones. Filtro con `PROJ-1234`,
`open` o `draft`, y Enter reanuda la sesión en su directorio con `ccr`.

Desde tmux uso dos atajos.

- `prefix G` abre un popup con fzf sobre todos los panes de tmux, con la
  ventana, el nombre y el título de cada sesión de Claude. Enter me lleva al
  pane.
- `prefix g` abre un pane flotante que acepta texto libre ("pr 2032", "el del
  timeout"). Un modelo pequeño (haiku, vía `claude -p`) elige la sesión y me
  lleva a su pane, o la reanuda en una ventana nueva si está cerrada. Tarda
  unos 3 segundos.

![Popup de prefix G: fzf sobre todos los panes de tmux con ventana, nombre de la sesión de Claude y título, y una vista previa del pane](/images/tmux-pane-picker.png)

También es un skill de Claude Code, así que "vuelve a la sesión de la PR
2032" funciona desde un chat.

### Tres sesiones de tmux: `doing`, `parked` y `oncall`

_Actualización, noviembre de 2026: ahora tengo unas ocho sesiones de tmux, una
por tema, y ya no uso `parked` ni la ventana `board`. La idea es la misma._

- **`doing`** guarda lo que llevo ahora, sea una sesión trabajando, una que
  espera mi respuesta o una con una PR o un ticket abierto. Su primera ventana es `board`,
  un Claude fijo sin tarea que uso como centro de control.
- **`parked`** guarda lo terminado o en pausa que quiero mantener abierto.
- **`oncall`** es para la guardia. Va aparte para que una alerta no se mezcle
  con el trabajo del día.

### Claude ordena las ventanas

Las ventanas cambian de estado todo el rato. Una PR se mergea, o una sesión
aparcada vuelve a hacer falta. Desde `board` le pido a Claude que las ordene
con el skill `tmux-board`.

Claude lee el resumen de cada sesión y el estado de sus PRs y tickets.
Propone qué va a `doing` y qué a `parked`, y nombres mejores para las
ventanas con uno genérico. Solo las mueve cuando le digo que sí.

Usa `move-window`, así que la ventana se lleva su proceso, su `ccr` con el
uuid y su icono. resurrect restaura cada sesión de tmux con su nombre.

## No olvidar trabajo

Se me olvidaba trabajo, como una sesión que se quedó a medias o un ticket
desplegado que nadie validó.

### `/todo` y la ventana `board`

`/todo` es un skill de Claude Code, también sin publicar. Tira del MCP de
Atlassian, de `gh` y del índice de sesiones, y junta en una sola vista:

- mis tickets de Jira asignados y los cerrados en la última semana,
- mis PRs abiertas, las reviews que me piden y las mergeadas en 7 días,
- las ventanas de `doing` donde hay una sesión trabajando, con su resumen,
- los tickets desactualizados que apuntó el índice de sesiones.

Los tickets desactualizados los apunta un hook. Al cerrar una sesión,
`SessionEnd` llama a `cc-session-end`, que mira si la sesión dejó algún
ticket desactualizado (PR mergeada con el ticket aún abierto, por ejemplo).
Lo guarda en `~/.claude/ticket-followups.tsv` y lo muestra 8 segundos en la
barra. Nunca toca Jira.

`/todo` lo une todo por ticket y lo reparte según de quién es el siguiente
movimiento:

```
## Te toca
| Ticket            | Siguiente paso             | Ventana |
| PROJ-1234 timeout | validar en producción      | doing:4 |
| PROJ-1235 tokens  | empezar (2 semanas en To Do) |         |

## Esperas a otros
- PROJ-1236 → review de un compañero en repo#123 · doing:6

## Terminado (7 días)
- Tickets: PROJ-1230, PROJ-1231
```

Cada fila dice el siguiente paso y la ventana, así que salto a ella con
`prefix G`. PROJ-1235 es el tipo de ticket que se me perdía, dos semanas en
To Do y ninguna sesión abierta.

Lanzo `/todo` desde `board`. Si una tarea pendiente necesita su propia
sesión la abro con `cc-spawn`, o vuelvo a la que ya existía con `prefix g`.

## Repartir trabajo entre sesiones

En mitad de una tarea veía un arreglo que no tocaba, o quería separar el
diseño de la ejecución. Cambiar de sesión me hacía perder el hilo.

### `cc-spawn`

```bash
cc-spawn [-p] [-w <branch>] <name> [dir]
```

Abre una ventana nueva (o un pane con `-p`) que ejecuta
`ccr <uuid> --name <name>` y devuelve el uuid de la sesión.

- `-w <branch>` lanza la sesión en `<repo>/.worktree/<branch>` (las `/` de
  la rama pasan a `-`) y crea el worktree desde `origin/main` si no existe.
  Así varias sesiones tocan el mismo repo sin pisarse.
- El pane solo lleva `ccr` con su uuid, nunca el prompt de la tarea, porque
  resurrect volvería a enviar el prompt en cada reinicio. La tarea la escribo
  luego, o se la manda la sesión que abrió el pane.

Desde tmux, `prefix C` pide un nombre y lanza `cc-spawn` en el directorio
actual.

Como mejor funciona `cc-spawn` es desde una sesión de Claude. En
`login-timeout` veo que el README está viejo y le digo a la sesión que lo
arregle aparte. Lanza `cc-spawn -w docs-readme docs-readme`, le pasa la tarea
en un archivo con un mensaje entre sesiones (`SendMessage`) y sigue con lo
suyo. Cuando el README está listo, me lo dice en una línea.

![Demo animada: en login-timeout pido actualizar el README aparte, la sesión lanza cc-spawn, aparece la ventana 5 docs-readme en amarillo, pasa a verde y vuelve una línea a la primera sesión](/images/tmux-cc-spawn.gif)

Las dos sesiones pueden seguir hablando en las dos direcciones. Yo solo miro
la ventana nueva si el icono se pone rojo.

## Extras

### Popups

Para un comando rápido tenía que abrir un pane y cerrarlo después. Los
popups se abren encima del layout y desaparecen al terminar:

| Tecla | Qué hace                                     |
| ----- | -------------------------------------------- |
| `s`   | elegir sesión con fzf y preview              |
| `P`   | hacer attach a otra sesión                   |
| `Z`   | tmux-sessionizer (sesión por proyecto)       |
| `O`   | navegar sesiones con tmux-oil.nvim           |
| `D`   | editar los dotfiles, commit y push al cerrar |
| `J`   | buscar tickets de Jira                       |
| `N`   | crear un ticket                              |

`T` no es un popup. Abre `TODO.md` en un split del 20% a la izquierda.
`tmux-fzf-session` y `tmux-sessionizer` están en los dotfiles. `jira-fzf` y
`jira-new` son scripts míos sin publicar sobre el CLI de Jira.

### Plugins

```tmux
set -g @plugin 'tmux-plugins/tpm'  # Plugin Manager
set -g @plugin 'tmux-plugins/tmux-sensible'  # A set of tmux options that should be acceptable to everyone.
set -g @plugin 'tmux-plugins/tmux-resurrect' # Restore tmux environment
set -g @plugin 'tmux-plugins/tmux-continuum' # automatic restore and continuous saving of tmux env
set -g @plugin 'tmux-plugins/tmux-open' # open on selection: o, c-o, s-s
set -g @plugin 'wfxr/tmux-fzf-url' # fzf for urls in tmux: c-u
```
