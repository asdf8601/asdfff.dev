**En una frase:** cada chat de Claude Code vive en su propia ventana de tmux,
vuelve a su conversación exacta tras un reinicio, y la barra de estado me dice
cuál me está esperando.

## Qué tengo y por qué

1. **Prefijo `C-a` y movimiento estilo vim.** Mis dedos ya saben vim, y
   `C-a` queda más cerca que `C-b`.
2. **Splits en el directorio actual.** Casi siempre abro un pane para hacer
   algo en la misma carpeta.
3. **Popups para todo lo que no es código.** Busco una sesión, un ticket o
   apunto un TODO sin romper el layout.
4. **Wrapper `ccr` para Claude Code.** Para que cada pane vuelva a su chat y
   no al último chat del directorio.
5. **`cc-spawn` para lanzar sesiones.** Abrir un Claude con nombre, en su
   ventana y si hace falta en su propio worktree, con una tecla.
6. **Autosave con resurrect y continuum.** Si se reinicia el Mac, recupero
   todas las ventanas sin pensar.
7. **Estado de Claude en la barra.** Con diez sesiones abiertas no puedo ir
   mirando una a una cuál ha terminado.
8. **Índice de sesiones (`sessions`).** Con tantas ventanas y chats
   viejos, buscar a ojo dónde estaba el chat de una PR es lento.
9. **`/todo` para saber qué me toca.** Tickets, PRs y ventanas están en
   sitios distintos, y quiero verlos juntos con el siguiente paso.
10. **Ventanas con nombre automático.** El nombre de la ventana dice de qué
   va la sesión, no el directorio.
11. **Avisos por Telegram.** Las notificaciones del escritorio no atraviesan
   tmux.

La config vive en mis dotfiles: `~/.dotfiles/macos/home/.tmux.conf`.

## 1. Prefijo y movimiento

```tmux
set -g prefix C-a
set -g base-index 1
set-option -g status-position top
set-option -g detach-on-destroy off
set -g mouse off
```

- `h j k l` para moverse entre panes, `M-h/j/k/l` para redimensionar.
- `b` vuelve a la última ventana.
- `S` y `V` traen otra ventana como pane.
- `m` enciende o apaga el ratón, que por defecto está apagado.
- La barra va arriba y `detach-on-destroy off` hace que cerrar una sesión
  me lleve a otra en vez de sacarme de tmux.

## 2. Splits en el directorio actual

```tmux
bind i split-window -h -c "#{pane_current_path}"
bind / split-window -h -c "#{pane_current_path}"
bind - split-window -c "#{pane_current_path}"
bind c new-window -c "#{pane_current_path}"
```

`i` o `/` en vertical, `-` en horizontal, `c` ventana nueva. Todos heredan
el directorio del pane donde estoy.

## 3. Popups

Se abren encima del layout y desaparecen al terminar:

| Tecla | Qué hace                                     |
| ----- | -------------------------------------------- |
| `s`   | elegir sesión con fzf y preview              |
| `P`   | hacer attach a otra sesión                   |
| `Z`   | tmux-sessionizer (sesión por proyecto)       |
| `T`   | `TODO.md` en un split al lado                |
| `O`   | navegar sesiones con tmux-oil.nvim           |
| `D`   | editar los dotfiles, commit y push al cerrar |
| `J`   | buscar tickets de Jira                       |
| `N`   | crear un ticket                              |

## 4. El wrapper `ccr`

tmux-resurrect guarda el comando de cada pane y lo relanza al restaurar. El
problema es que `claude --continue` abre el último chat del directorio, así
que si tengo cinco panes en la misma carpeta, los cinco vuelven al mismo
chat.

`ccr` (con `alias cc=ccr`) fija un uuid de sesión en su propia línea de
comandos:

```zsh
#!/bin/zsh
if [[ "$1" == -* ]]; then
  exec claude "$@"
fi

id="$1"
if [[ "$id" =~ '^[0-9a-f]{8}-[0-9a-f]{4}-[0-9a-f]{4}-[0-9a-f]{4}-[0-9a-f]{12}$' ]]; then
  shift
else
  exec "$0" "$(uuidgen | tr '[:upper:]' '[:lower:]')" "$@"
fi

session_files=(~/.claude/projects/*/"$id".jsonl(N))
if (( ${#session_files} )); then
  claude --resume "$id" "$@"
else
  claude --session-id "$id" "$@"
fi
```

- Sin argumentos se relanza a sí mismo con un uuid nuevo, así el uuid queda
  en el `argv` del proceso, que es lo que guarda resurrect.
- Ejecuta `claude` como hijo y no con `exec`, porque el proceso de `claude`
  aparece en `ps` sin argumentos.
- Con un uuid que ya existe hace `--resume`. Para anclar un chat viejo a un
  pane: `cc <uuid>`.
- Con flags (`cc -c`, `cc -r`) pasa todo tal cual a `claude`.

## 5. `cc-spawn`

```bash
cc-spawn [-p] [-w <branch>] <name> [dir]
```

Abre una ventana nueva (o un pane con `-p`) que ejecuta
`ccr <uuid> --name <name>` y devuelve el uuid de la sesión.

- Con `-w <branch>` la sesión corre en `<repo>/.worktree/<branch>`, y si el
  worktree no existe lo crea desde `origin/main`. Así puedo tener varias
  sesiones tocando el mismo repo sin pisarse.
- El pane solo lleva `ccr` con su uuid, nunca el prompt de la tarea: resurrect
  relanza ese comando al restaurar, y un prompt ahí se volvería a enviar en
  cada reinicio. La tarea se le pasa después.

Desde tmux, `prefix C` pide un nombre y lo lanza en el directorio actual:

```tmux
bind C command-prompt -p "claude session name:" "run-shell '$HOME/.local/bin/cc-spawn %1 #{pane_current_path} >/dev/null'"
```

## 6. Autosave

```tmux
set -g @resurrect-processes '~ipython ~ccr "~claude->claude --continue"'
set -g @resurrect-strategy-nvim 'session'
set -g @continuum-restore 'on'
set -g @continuum-save-interval '5'
```

Guarda cada 5 minutos y restaura al arrancar tmux. Relanza `ccr`, `ipython`
y `claude` (este último con `--continue`), y nvim con su sesión.

### Cuidado con `prefix r`

Recargar la config (`source-file`) machaca `status-right`, y tmux-continuum
guarda las sesiones a través de un comando metido en `status-right`. Tras
recargar, el autosave se moría en silencio hasta el siguiente reinicio. Me
enteré cuando un reinicio me devolvió un layout de dos semanas antes.

El arreglo es poner el hook a mano en la config, con la misma ruta absoluta
que usa el plugin:

```tmux
set -g status-right "#($HOME/.tmux/plugins/tmux-continuum/scripts/continuum_save.sh) %Y-%m-%d  %H:%M "
```

Para comprobarlo después de recargar (tiene que dar 1):

```bash
tmux show-option -gv status-right | grep -c continuum_save
```

## 7. Estado de Claude en la barra

Unos hooks de Claude Code (`UserPromptSubmit`, `Stop`, `Notification`,
`SessionEnd`) llaman a un script, `cc-tmux-state`, que guarda el estado de
cada pane y pinta un icono delante del nombre de la ventana: trabajando,
terminado o pidiendo permiso.

```tmux
setw -g window-status-format " #I #{@cc}#[default]#W "
set-hook -g pane-focus-in 'run-shell -b "$HOME/.local/bin/cc-tmux-state seen #{pane_id}"'
```

El hook `pane-focus-in` marca el pane como visto, así una ventana solo pide
atención hasta que la miras.

Con `prefix A` abro un popup con los panes que me esperan: primero los que
piden permiso, luego los turnos terminados que no he mirado.

## 8. Índice de sesiones

`sessions.py` lee todos los transcripts de `~/.claude/projects/` y guarda un
índice local con una línea por sesión: última actividad, directorio, título
y las PRs y tickets que esa sesión tocó de verdad (abrió la PR, hizo push,
movió el ticket), con su estado en vivo.

```bash
python3 ~/.claude/skills/sessions/sessions.py [all] [query] [--sync]
```

Sin argumentos abre fzf sobre todas las sesiones. Escribo `GC-1234`, `open`
o `draft` para filtrar, y Enter reanuda la sesión en su directorio con `ccr`.

Desde tmux uso dos atajos:

```tmux
bind g new-pane -O -x 60% -y 30% -X 20% -Y 35% "python3 $HOME/.claude/skills/sessions/sessions.py ask"
bind G display-popup -E -w 80% -h 70% "python3 $HOME/.claude/skills/sessions/sessions.py panes"
```

- `prefix G` abre fzf sobre todos los panes de tmux, con la ventana, el nombre
  y el título de cada sesión de Claude. Enter me lleva al pane.
- `prefix g` acepta texto libre ("pr 2032", "el del timeout"). Un modelo
  pequeño (haiku) elige la sesión que encaja y me lleva a su pane; si la
  sesión ya no está abierta, la reanuda en una ventana nueva.

Al cerrar una sesión, el hook `SessionEnd` mira si dejó algún ticket
desactualizado (PR mergeada con el ticket aún abierto, por ejemplo) y lo
apunta en la barra de estado. No toca Jira, solo avisa.

También es un skill de Claude Code, así que puedo pedirle "vuelve a la
sesión de la PR 2032" y lo resuelve con el mismo script.

## 9. `/todo`

Es un skill de Claude Code. Junta en una sola vista:

- mis tickets de Jira asignados y los cerrados en la última semana,
- mis PRs abiertas, las reviews que me piden y las mergeadas en 7 días,
- las ventanas de tmux donde hay una sesión trabajando, con su resumen,
- los tickets desactualizados que apuntó el índice de sesiones.

Lo une todo por ticket y lo reparte en tres secciones según de quién es el
siguiente movimiento:

```
## Te toca
| Ticket          | Siguiente paso              | Ventana |
| GC-1234 timeout | validar en producción       | doing:4 |
| GC-1235 tokens  | empezar (30 días en To Do)  |         |

## Esperas a otros
- GC-1236 → review de un compañero en repo#123 · doing:6

## Terminado (7 días)
- Tickets: GC-1230, GC-1231
```

Cada fila dice qué hacer y en qué ventana está la sesión que lleva ese
ticket, así paso directo de "qué toca" a la ventana con `prefix G`.

## 10. Nombre automático

Por defecto la ventana se llama como su directorio:

```tmux
set-option -g automatic-rename on
set-option -g automatic-rename-format '#{b:pane_current_path}'
```

Para las ventanas de Claude, el hook `Stop` llama a `cc-tmux-name`, que
renombra la ventana con el título de la sesión. Así la barra dice "fix
timeout" y no "seedtag" diez veces.

## 11. Avisos por Telegram

Las notificaciones de escritorio de Ghostty no atraviesan tmux (probé OSC 9
y 777, con y sin `allow-passthrough`). Cuando quiero que me avisen de que
algo terminó, me mando un Telegram.
