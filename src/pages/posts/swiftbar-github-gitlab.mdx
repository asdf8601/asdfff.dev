Quería ver de un vistazo que PRs tengo que atender de un vistazo. Lo resuelvo
rapidisimo con
[SwiftBar](https://github.com/swiftbar/SwiftBar), un script de bash y `jq`.

![Menú de SwiftBar con reviews pedidas y mis PRs](/images/swiftbar-menu.png)

## La idea

SwiftBar ejecuta un script cada X tiempo y pinta el stdout en la barra de
menús. Eso es todo.

- El nombre del archivo marca el intervalo: `github.10m.sh` (cada 10 min).
- Lo que va antes del primer `---` sale en la barra. Lo de después, en el menú
desplegable.
- Cada línea acepta parámetros detrás de una barra vertical: `texto | href=URL color=red`.

## Requirements

```bash
brew install --cask swiftbar
brew install gh glab jq
gh auth login
glab auth login
mkdir -p ~/swiftbar   # elígela como carpeta de plugins al abrir SwiftBar
```

## MVP


```bash
# create file
cat > ~/swiftbar/mvp.5m.sh <<'EOF'
#!/usr/bin/env bash
export PATH="/opt/homebrew/bin:/usr/local/bin:$PATH"
prs=$(gh search prs --author=@me --state=open --json number,title,url,repository)
echo "PRs $(jq length <<<"$prs")"
echo "---"
jq -r '.[] | "\(.repository.name)#\(.number) \(.title | gsub("\\|"; "/")) | href=\(.url)"' <<<"$prs"
EOF

# make it executable
chmod +x ~/swiftbar/mvp.5m.sh

# run it
open -g 'swiftbar://refreshallplugins'
```

Si ves `PRs N` en la barra, funciona. Lo demás es lo mismo con más filtros.

## GitHub

Reviews que te piden + tus PRs con estado de CI, en una sola query.

```bash
#!/usr/bin/env bash
# <swiftbar.hideRunInTerminal>true</swiftbar.hideRunInTerminal>
# <swiftbar.hideAbout>true</swiftbar.hideAbout>

export PATH="/opt/homebrew/bin:/usr/local/bin:$PATH"
unset GH_TOKEN GITHUB_TOKEN

query='
fragment pr on PullRequest {
  number title url
  repository { nameWithOwner }
  commits(last: 1) { nodes { commit { statusCheckRollup { state } } } }
}
query {
  mine: search(query: "is:open is:pr archived:false author:@me", type: ISSUE, first: 50) { nodes { ...pr } }
  review: search(query: "is:open is:pr archived:false user-review-requested:@me", type: ISSUE, first: 50) { nodes { ...pr } }
}'

if ! json=$(gh api graphql -f query="$query" 2>&1); then
  echo "GH !"; echo "---"; echo "gh falló | color=red"; exit 0
fi

jq -r '
def ci: {"SUCCESS": "✓", "FAILURE": "✗", "ERROR": "✗", "PENDING": "…"}[.commits.nodes[0].commit.statusCheckRollup.state // ""] // "";
def row: "\(.repository.nameWithOwner)#\(.number) \(.title | gsub("\\|"; "/")) \(ci) | href=\(.url)";
.data as $d
| "👀 \($d.review.nodes | length) 📝 \($d.mine.nodes | length)",
  "---", "Review pedida", ($d.review.nodes[] | row),
  "---", "Mis PRs", ($d.mine.nodes[] | row)
' <<<"$json"
echo "---"
echo "Refresh | refresh=true"
```

- Los filtros son los de la búsqueda de github.com/pulls. Pruébalos ahí primero.
- `user-review-requested` y no `review-requested`, que mete las peticiones a tus equipos.
- Para más secciones: `mergeStateStatus` (`DIRTY` = conflictos, `CLEAN` = listo), `reviewDecision`, `isDraft`.

## GitLab

Igual, con `glab`. Este todavía no lo he probado.

```bash
#!/usr/bin/env bash
# <swiftbar.hideRunInTerminal>true</swiftbar.hideRunInTerminal>
# <swiftbar.hideAbout>true</swiftbar.hideAbout>

export PATH="/opt/homebrew/bin:/usr/local/bin:$PATH"
unset GITLAB_TOKEN
# export GITLAB_HOST=gitlab.example.com   # si es self-hosted

query='
fragment mr on MergeRequest {
  iid title webUrl draft detailedMergeStatus
  project { fullPath }
  headPipeline { status }
}
query {
  currentUser {
    mine: authoredMergeRequests(state: opened, first: 50) { nodes { ...mr } }
    review: reviewRequestedMergeRequests(state: opened, first: 50) { nodes { ...mr } }
  }
}'

if ! json=$(glab api graphql -f query="$query" 2>&1); then
  echo "GL !"; echo "---"; echo "glab falló | color=red"; exit 0
fi

jq -r '
def ci: {"SUCCESS": "✓", "FAILED": "✗", "RUNNING": "…", "PENDING": "…"}[.headPipeline.status // ""] // "";
def row: "\(.project.fullPath)!\(.iid) \(.title | gsub("\\|"; "/")) \(ci) | href=\(.webUrl)";
.data.currentUser as $u
| ($u.mine.nodes | map(select(.draft | not))) as $mine
| ($mine | map(select(.detailedMergeStatus == "MERGEABLE"))) as $ready
| "🦊 👀 \($u.review.nodes | length) 🚀 \($ready | length)",
  "---", "Review pedida", ($u.review.nodes[] | row),
  "---", "Listas para merge", ($ready[] | row),
  "---", "Mis MRs", ($mine[] | row)
' <<<"$json"
echo "---"
echo "Refresh | refresh=true"
```

- `detailedMergeStatus` te dice qué bloquea: `CONFLICT`, `NOT_APPROVED`, `CI_MUST_PASS`, `DISCUSSIONS_NOT_RESOLVED`.
- Un plugin por proveedor. Si una falla, el otro sigue.

## Chuleta

| Parámetro                           | Qué hace                                          |
| ----------------------------------- | ------------------------------------------------- |
| `href=URL`                          | Abre la URL al hacer clic                         |
| `color=red`                         | Color del texto                                   |
| `length=70`                         | Recorta y pone el título entero en el tooltip     |
| `sfimage=nombre`                    | Icono SF Symbol                                   |
| `symbolize=false`                   | No convierte `:texto:` en iconos                  |
| `alternate=true`                    | Sustituye a la línea anterior con Option pulsado  |
| `bash=ruta param1=x terminal=false` | Ejecuta un script en segundo plano                |
| `refresh=true`                      | Re-ejecuta el plugin al hacer clic                |

- `--` delante de una línea = submenú de la anterior.
- Lo que sale debajo de Refresh en la captura lo añade SwiftBar. Se oculta con los metadatos `swiftbar.hide*`.

Metadatos útiles, en comentarios del script:

```bash
# <swiftbar.refreshOnOpen>true</swiftbar.refreshOnOpen>      # refresca al abrir el menú
# <swiftbar.schedule>*/10 9-19 * * 1-5</swiftbar.schedule>   # cron en vez del nombre
```

## Cuando falla

Pruébalo con el entorno vacío que usa SwiftBar:

```bash
env -i HOME=$HOME PATH=/usr/bin:/bin ~/swiftbar/github.10m.sh
```

- **No aparece:** falta `chmod +x`.
- **`command not found`:** SwiftBar no lee tu `.zshrc`. Pon el `export PATH` arriba.
- **Faltan repos:** hay un `GH_TOKEN` exportado que pisa el login. El `unset` lo arregla.
- **Fila rota:** un título con barra vertical. Para eso está el `gsub`.
- **Datos viejos:** el script falló en silencio. Imprime un título de error y `exit 0`.
- **Rate limit:** una sola query GraphQL y 5 a 10 min de intervalo.

No metas tokens en los scripts.
